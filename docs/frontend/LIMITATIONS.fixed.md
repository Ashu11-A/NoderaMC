## §2 — Android

M-2 retired on 2026-08-04: the node now outlives the screen going off, because a foreground service
owns it instead of an Activity.

| id | Was | Retired by | Evidence |
|---|---|---|---|
| M-2 | The node stopped when Android stopped the app — the worker is a daemon thread in the app process, so a phone holding committee seats took them all down with it when the app was reclaimed (observed ~25 min into a session, and every peer it served lost it silently) | `NoderaWorkerService` (`dataSync`, `START_STICKY`) owns `NoderaWorker.start`, with `startForeground` and an ongoing notification on its own `nodera-node` channel. The manifest permissions (`FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_DATA_SYNC`, `WAKE_LOCK`), the `<service>` element and the notification strings are patched by `scripts/android-apk.sh` — `app/gen/android` is regenerated, so hand-edits there do not survive — and the script `die`s if the service is missing from the packaged manifest. **A foreground service extends a process's lifetime rather than guaranteeing it, so the exit test is a measurement, not a proof** | One hour backgrounded with the screen off, on a physical device: the same `pid=2605` at minute 0 and minute 60, `isForeground=true foregroundId=1 types=0x00000001 foregroundNoti=Notification(channel=nodera-node … ONGOING_EVENT\|FOREGROUND_SERVICE)`, `mWakefulness=Dozing` throughout, `NODERA-OK 2 0.1.0` from `127.0.0.1:25610` at the hour — and the worker *working* the whole time, logging archive seeder lookups every second through minute 61. Trap for whoever re-runs it: each `adb` poll can wake the device, so check at the start and at the hour, not every minute |

Four rows retired on 2026-07-28: the Android bytecode guard now runs in CI (and caught a live
regression on its first run), the SDK pins agree, a tracker store reaches a running worker, and the
Restart button is no longer offered where nothing can honour it.
