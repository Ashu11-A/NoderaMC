| L-86 | **R1 — a positional body cannot be extended.** Message bodies are fixed-width fields written back to back, and nothing below the frame carries its own length, so a decoder cannot skip a field it does not know. Adding one field to `NodeCapabilities` or `PeerEntry` does not degrade for an un-upgraded reader — it makes the rest of the enclosing message decode as garbage or underflow. The consequence is not a rough edge but the defining one: **there is no such thing as a compatible change**, which is why every cross-version symptom in this register traces here. The same fault makes truncation undetectable where a trailing field is optional — a `PeerJoin` cut before `clientVersion` is byte-for-byte a valid legacy frame, which `CanonicalMutationFuzzTest` documents as its one truncation exception | [14](Task.14.md) | A field appended to an infrastructure message is ignored by a peer built before it, in a test that decodes the new frame with the old schema — `ForwardCompatibilityTest.aFieldAppendedByANewerPeerIsIgnored` + `aFieldAppendedInsideANestedStructureIsIgnored` + `aFieldTheSenderOmitsTakesItsDocumentedDefault`, and `CrossVersionIT.aFutureFieldSurvivesARelay`. Fixed by the `NDR2` frame and canonical TLV bodies: every field carries its own length, so an unknown one is skipped, kept, and re-emitted verbatim. Both fuzz exceptions the harness documented are gone — `PeerJoin` truncation is now detectable, and `RegionRefusal` preserves its raw reason code | RETIRING |
| L-87 | **R2 — nothing is negotiated before admission.** `ClientHello`/`ServerHello`/`ChallengeResponse`/`WorkerActivation` (tags 1–4) exist only in the codec and its tests; no runtime handler constructs or consumes them. ## Reading guide for the implementing model

- The trust model is the constraint that shapes most decisions here: services are **hints**, peers
  verify everything. Any proposal that makes a service load-bearing for correctness is a design bug,
  not a limitation.
- Bounding is a security property in this category. Any new cache keyed by remote input must be
  bounded in the commit that introduces it.
- Frozen wire discipline: an appended tag needs a Java record, a golden fixture, and the Rust mirror
  in the same commit. A tag appended on one side alone fails CI, by design.
- When a design choice trades against a §B entry, prefer the choice that keeps the exit test
  achievable.
