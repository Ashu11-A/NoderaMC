| L-82 | The updater fetched over a `curl` subprocess, so a host without `curl` on `PATH` could not self-update | Replaced by `update::HttpsFetcher`, an in-process client (`ureq` + `rustls` with bundled webpki roots — no OpenSSL, no CA files needed by a static musl binary), which is now the **default** at all three construction sites. Going further than the recorded elimination path was the deployment's doing: the published images are `alpine` with one static binary, and `curl` is exactly what they do not have, so a cargo feature defaulting to `curl` would have shipped a lane that never worked in the place it matters. `CurlFetcher` survives for hosts whose proxy/CA/`.curlrc` configuration this code has no business duplicating. Exit test, both halves: `a_missing_curl_still_says_what_to_do_about_it` asserts the absence message (reachable now that the program name is a field), and `a_response_larger_than_the_ceiling_is_refused_rather_than_allocated` + `the_default_fetcher_reads_a_body_it_is_allowed_to_read` drive the native fetcher against a real socket. Verified in the image: `docker run nodera-tracker` starts and drains with no `curl` present | [5](Task.5.md) | 2026-07-27 |
| L-44 | The tracker was **embedded in a Java peer**, so the world list and announce surface died with its host peer — there was no always-on discovery infrastructure | The standalone Rust `nodera-tracker` serves the frozen discovery family plus the appended announce family. `TrackerServiceIT` spawns the **real release binary** and drives it from Java peers: two peers announce two worlds with per-world isolation; a JDK-`NodeIdentity`-signed announce is verified inside the service by `ed25519-dalek`; a tampered record is refused with `bad-signature` and never reaches the registry; a `STOPPED` announce removes a peer immediately; and — the row's actual exit — **a world whose every Java seeder has gone silent past the TTL is still listed by name, with its countdown and a DEAD verdict**, which the embedded tracker could not do. The embedded `TrackerService` and its tests were deleted; `PeerDirectory` and `ArchiveInventory` remain as peer-local caches | [1](Task.1.md) | 2026-07-19 |
