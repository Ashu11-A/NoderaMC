**The byte-exact Rust port of the canonical encoding.** It exists so the Java implementation cannot
drift, and so the Rust services can speak the peers' own protocol rather than a second one.

- **Depends on:** nothing in the project — it is the boundary.
- **Depended on by:** `nodera-tracker`, `nodera-rendezvous`.
- **Docs:** [`docs/network/Task.1.md`](../../docs/network/Task.1.md)

---

## Architecture

```
rust/nodera-codec/src/
├── lib.rs         the crate surface
├── writer.rs      the canonical writer — fixed widths, tag + version prefix, sorted collections
├── reader.rs      the canonical reader, with bounds checked before allocation
├── types.rs       the domain value types the wire carries
├── messages.rs    the message family (append-only tags)
├── rendezvous.rs  the rendezvous/relay family
├── tags.rs        the type- and message-tag registry — mirrored against Java
├── sig.rs         Ed25519 verification (verify-only; this crate holds no keys)
└── framing.rs     u32-length framing with a hard cap, matching the socket transport

rust/nodera-codec/tests/
├── fixtures.rs    re-encode every Java-emitted golden frame and compare byte-for-byte
└── tag_mirror.rs  fail if a tag exists on one side and not the other
```

## Why it is shaped this way

**Two implementations that must agree byte-for-byte are a test.** A single canonical encoder is
trusted; two that are held to the same golden frames catch encoder drift that no unit test on either
side would notice — a reordered field, a width change, an ordering assumption that happened to hold.

**Java emits, Rust re-encodes.** The direction matters. Java owns the contract, so fixtures are
generated there and this crate proves it can reproduce them exactly. Hand-editing a fixture to make
this side pass would destroy the only mechanism keeping the two honest.

**Tag mirroring fails CI, deliberately.** A tag appended on one side alone is the most likely way for
the two implementations to diverge, and it would otherwise be invisible until a message arrived in
production. The mirror test makes it a build failure.

**Verify-only signatures.** This crate can check an Ed25519 signature and cannot create one. The
services that depend on it hold no keys, so the capability simply does not exist there.

**Bounds before allocation.** Every length read from the wire is checked before anything is allocated.
The services using this crate are exposed on the public internet, so a length field is attacker input.

## Rules

- Appending a tag means appending it in `java/transport` **in the same commit**, with a golden fixture.
- Never renumber or reuse a tag.
- Never hand-edit a file under `fixtures/wire/` — regenerate it from Java.
- This crate carries **no** game, consensus, or storage logic. It is encoding and verification only.
