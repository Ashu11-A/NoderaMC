## The three normative documents

Everything under this section is mirrored from the repository rather than rewritten for the site, because these are documents that already have to be correct and a second copy of them would start being wrong immediately.

<a href="/docs/develop/wire-protocol">**The wire protocol**</a> is the frame, its message families, and the rules under which two builds from different releases negotiate what they can say to each other.
Read it before you touch anything that puts bytes on a socket.

<a href="/docs/develop/engine-sdk">**The engine SDK**</a> is the deterministic region engine's public surface, and the rules a caller has to keep to in order to stay deterministic.
Determinism is the project's central bet: if two honest peers cannot reproduce the same result from the same inputs, nothing downstream works.

<a href="/docs/develop/mod-compatibility">**Mod compatibility**</a> is what another mod may and may not do inside a validated region.
It is written for mod and modpack authors rather than for contributors, and it is the answer to "will my pack work".

<a href="/docs/develop/roadmap">**The roadmap**</a> is the derived index of every task in every category, with its status and what it depends on.

## The shape of the repository

One tree holds the deterministic engine and the network stack in Java, the tracker and relay services and the shared core in Rust, the NeoForge mod, the headless peer worker, the desktop and Android companions, and this website.

Which directory holds which component is not something to memorise or to hard-code: there is a single manifest at the root that names them, and everything that needs a path — the build, the scripts, the tests, the tooling — reads it.
Spelling a directory anywhere else is the mistake the manifest exists to prevent.

## The gate

Two test suites, both required, neither optional: the Java gate and the Rust workspaces.
The Android and desktop companions are held to the same standard.

A change lands green or it does not land.
The repository has a specific, unusually strict rule about this that is worth knowing before you open a pull request: **the interfaces may not claim capabilities the system does not have.**
That is enforced by tests, not by review — including on this website, where every capability claim on the landing page and in these docs has a row naming the repository file that backs it, and the build fails when either side moves.
