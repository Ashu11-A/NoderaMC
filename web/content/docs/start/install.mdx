## The order matters

Install the **companion app first**, then the mod.

The mod does not work on its own.
It talks to a headless worker process on your own machine, and the app is what installs and supervises that worker.
If you drop the jar in `mods/` and start the game with nothing running, the mod aborts startup and shows you an install prompt — which is the correct behaviour, but it is a worse first five minutes than doing it in this order.

<Callout type="note" title="What you need before starting">
  Minecraft **1.21.1**, **NeoForge 21.1.238**, and **Java 21**.
  These are pinned rather than "or later": the mod reaches into the game's internals to run regions deterministically, and a different Minecraft or NeoForge build is a different set of internals.
</Callout>

Take the installer for your platform from <a href="/download">the download page</a>.

Start the app once after installing.
It unpacks the worker, generates this install's identity, and starts listening on <Tag>127.0.0.1:25610</Tag>.
Nothing is announced to any network until you share a world.

## 2. Install the mod

Put `nodera-neoforge-<version>.jar` into your NeoForge 1.21.1 profile's `mods/` folder.

That is the whole installation.
There is no separate library jar and no config to write before the first launch.

<Callout type="warning" title="Everyone in the world needs it">
  Every player in a NoderaMC world runs the mod and joins as a peer.
  There is no vanilla lane, and the handshake enforces that rather than merely recommending it.
  If you want to play with someone who will not install anything, the feature you want is
  <a href="/docs/start/play-without-the-mod"> the LAN tunnel</a>, which is a different mechanism.
</Callout>

## 3. Start the game

Launch Minecraft with the app running.

The quickest check that the two halves found each other is the multiplayer screen: NoderaMC replaces it with its own, and a Nodera screen you can open is a worker the mod reached.

## If the game closes on startup

The message will name the reason, and one reason accounts for most of them.

**"Nothing answered on `127.0.0.1:25610`."**
The worker is not running.
Open the companion app and leave it running, then start the game again.
If the app is running and the game still cannot reach it, something on your machine is holding that port or blocking loopback traffic — a local firewall or a security suite with a "block all local servers" setting is the usual culprit, not the app.

You can turn the requirement off by setting `companion.required = false` in `config/nodera-client.toml`, and it is worth knowing what that actually buys you: the game will start, and every NoderaMC feature will be inert, because there is no node.
It is a way to load a profile that has the jar in it, not a way to play without the worker.

## What is installed where

<Callout type="details" title="For the curious, or for uninstalling">
  The app installs itself the way any application on your platform does, and it unpacks the worker
  alongside itself.
  Per-install state — your node's identity, the worlds you host, the pieces you hold for other
  people's worlds — lives in a `~/.nodera` directory rather than inside the game.
  Your Minecraft saves are untouched: NoderaMC reads and writes a world through the game, never
  behind its back.
</Callout>
